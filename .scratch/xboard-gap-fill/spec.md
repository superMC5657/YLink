## 1. 背景与目标

YLink 已完成核心交易闭环（账户/套餐/订单/支付/订阅/邀请/工单/管理端 13 模块）并投入联调，但与 Xboard 相比缺少一批**商业化外围能力**与**管理端深度操作**：

- 缺失独立模块：礼品卡、佣金提现、多支付渠道、插件/主题/在线更新、Telegram 机器人、运维监控界面等；
- 已有但深度不足：统计报表、批量操作、CSV 导出、手动标记支付等。

本 spec 的目标是逐项补齐这些缺口，形成与 Xboard 对等（或按商业场景取舍）的能力矩阵。

## 2. 对比口径

- 功能清单来源：Xboard `app/Http/Controllers/V1|V2` 全部控制器方法、`v2_*` 数据表、`plugins-core/` 支付插件目录、`theme/` 主题机制，对照 YLink `server/internal/router/router.go` 全量端点、`src/views` 前端页面、`server/migrations` 表结构。
- 优先级口径：P0 = 直接影响商业变现与营收闭环；P1 = 明显提升运营效率与数据决策；P2 = 生态/体验类，成本高、可缓排。

### ✅ F02 佣金提现（工单提现，仅代理商）（P0）

> **2026-08-28 已完成 ✅（第三批）**：`POST /invite/withdraw`（仅 `role=RoleAgent`，非代理商 13003/HTTP 403；提交即扣减 `commission_balance`，同事务行锁防双花，写 `commission_withdraws` 提现单 + `commission_logs` 提现流水 `biz_type=1`，`order_no='w<N>'`，订单号唯一约束改部分索引 `WHERE biz_type=0`）+ `GET /invite/withdraws`（本人记录）。管理端 `POST /admin/tickets/{id}/withdraw/pay|reject`：确认打款（流水 0→1）/ 拒绝（**自动退回佣金**，流水 0→2），均关闭工单 + 系统消息 + 审计（`withdraw_pay`/`withdraw_reject`）；提现单按 ticket_id 行锁，仅处理中可审（13004）。工单 `type` 字段区分（0/1），列表/详情带提现信息。**口径决策**：cron 佣金自动确认任务严格排除提现流水（`biz_type=0`），提现只能管理员手动确认——三态（提交/完成/退回）全程可追溯。前端：邀请页代理商专属提现入口/记录，管理端工单页审核操作。测试 4 例（提交/拒绝退回/确认/非提现工单拒绝）。
>
> **2026-08-28 二次调整：重新入选（范围收窄）。** 原随资金方向整体排除；用户决策恢复，收窄为最小闭环——**仅代理商**可发起，通过**工单**提交提现申请，管理员**手动确认并发放**（线下打款，系统内记账与审计）。原方案中的设置项（提现开关/方式白名单/最低额/限额）先不引入，见目标行为末条。

**现状**：YLink 佣金只能划转为余额（`POST /invite/transfer`，事务 + 行锁），无法提现；代理商身份已有完整链路（`agent_applies` 申请 → 管理员审批 → `role=RoleAgent`）；工单模块完备（`tickets.level` 0/1/2 为优先级语义、状态流转 0/1/2、重开一次）；佣金流水表 `commission_logs` 已有。

**目标行为**（最小闭环）：
1. **资格**：仅代理商可发起佣金提现——后端校验 `role=RoleAgent`（非代理商拒绝，403 类错误码），用户端仅对代理商显示提现入口；普通用户佣金仍仅可划转余额（`POST /invite/transfer` 保持不变）。
2. **提交**：用户端发送「佣金提现」工单（含提现方式 + 收款账号 + 金额）；提交时校验佣金余额充足，并在同一事务内**防双花**——提交即扣减 `commission_balance`（推荐，无需新迁移字段）或冻结，写 `commission_logs` 流水（`withdraw_submit`）；工单消息首条为结构化提现信息，或 `tickets` 扩展类型字段（实现口径：新增 `type` 字段优先，避免与 `level` 优先级语义混淆，实现阶段定）。
3. **管理员手动确认**：管理端工单列表/详情可区分提现工单；操作二选一——**确认打款**（标记已发放，线下打款由管理员线下执行，系统内将提现流水记为完成 `withdraw_paid`，工单关闭）或**拒绝**（自动**退回**佣金，写 `withdraw_refund` 流水，工单关闭）；两类操作均写 `audit_logs`。
4. **暂不做（可选增强）**：提现开关、提现方式白名单、最低提现额、每次/每日限额等设置项按最小闭环先不引入；资格校验 + 余额防双花已覆盖主要资损面，需要时再补。

**涉及模块**：`server`（工单类型扩展、提现提交/确认/拒绝端点、`commission_logs` 流水类型）、用户端工单/邀请页提现入口、管理端工单页操作按钮、`docs/api`、`docs/backend/data-model.md`。

**验收要点**：
- 仅代理商可发起：非代理商提交被后端拒绝，前端不显示入口。
- 提交时佣金余额校验 + 行锁防双花；重复提交相同提现受余额拦截（提交即扣减口径下天然拦截）。
- 拒绝/关闭提现工单必须自动退回佣金（防资损；退回写 `commission_logs` 流水，全程提交/退回/完成三态可追溯）。
- 确认打款与拒绝均写 `audit_logs`。
