# YLink 功能补齐 · 对齐 Xboard 缺口(Spec)

> **Status: closed**(2026-08-29 收口:全部入选需求已完成或明确关闭,仅 F17 缓排)
> 来源: YLink vs [cedar2025/Xboard](https://github.com/cedar2025/Xboard)(V2Board 系)功能对比盘点
> 范围: Xboard 有而 YLink 缺失或深度不足的功能,按优先级立项;YLink 独有能力(Tauri 桌面端/Go 栈/可观测性/代理审批)不在本文档范围
> 状态标识: ✅ 已完成;~~删除线~~ 明确不做;「缓排」= 暂不立项、有需求时再立项
> 各需求的端点契约见 [docs/api/README.md](../../docs/api/README.md) §16,实施提交见 git log

## 1. 背景与目标

YLink 已完成核心交易闭环(账户/套餐/订单/支付/订阅/邀请/工单/管理端)并投入联调,与 Xboard 相比缺少一批商业化外围能力与管理端深度操作(礼品卡、佣金提现、统计报表、批量操作、邮件/订阅模板、Telegram 机器人等)。本 spec 逐项补齐这些缺口,形成与 Xboard 对等(或按商业场景取舍)的能力矩阵。

## 2. 对比口径

- 功能清单来源: Xboard `app/Http/Controllers/V1|V2` 全部控制器方法、`v2_*` 数据表、`plugins-core/` 支付插件目录、`theme/` 主题机制,对照 YLink `server/internal/router/router.go` 全量端点、`src/views` 前端页面、`server/migrations` 表结构。
- 优先级口径: P0 = 直接影响商业变现与营收闭环;P1 = 明显提升运营效率与数据决策;P2 = 生态/体验类,成本高、可缓排。

## 4. 需求明细

已完成的条目只保留一句话范围;端点、数据模型与行为细节以 [docs/api/README.md](../../docs/api/README.md) 为准。

### ✅ F02 佣金提现(工单提现,仅代理商)(P0)

仅代理商(`role=RoleAgent`)通过工单提交提现申请,提交即扣减佣金余额防双花;管理端确认打款或拒绝(自动退回佣金),三态全程审计可追溯。

### ✅ F04 管理端统计报表增强(P1)

`GET /admin/stat/orders|users|traffic`(日趋势补零 + 套餐分布 + 用户/节点流量 Top10),前端「统计报表」页(ECharts 五图 + 时间范围切换)。

### ✅ F05 用户管理增强(P1)

CSV 流式导出、批量封禁/解封/调余额、管理端发邮件(mail_logs 留痕)、重置用户订阅密钥。

### ✅ F08 审计日志查询界面(P1)

`GET /admin/audit-logs` 只读查询(操作人/动作/目标/时间筛选 + 分页),目标按 action 翻译为可读展示(用户一律邮箱)。

### ✅ F09 节点批量操作/复制/排序(P1)

`POST /admin/servers/batch|sort`、`POST /admin/servers/{id}/copy`:整批单事务、逐节点结果汇总,复制重新生成 node_key。

### ✅ F10 订阅模板管理(P1)

三订阅生成器重构为 Go text/template,管理端维护自定义模板(编辑/预览/恢复内置);自定义缺失或渲染失败自动回退内置生成器,订阅不 5xx。

### ✅ F11 邮件模板管理(P2)

`mail_templates` 表 + 内置模板注册表(验证码/到期提醒/流量提醒);管理端编辑/测试发送/恢复默认,失败自动回退内置文案。

### ✅ F12 Telegram 机器人集成(P2)

验证码闭环绑定(一 chat 一账号)、webhook secret 校验、`enabled` 总开关、到期/流量提醒追加 TG 推送(失败仅记日志不阻断)。

### ✅ F14 会话管理界面(用户端)(P2)

会话列表(设备/IP/时间)+ 踢下线:被踢会话 access 立即 401,其余会话不受影响。

### ✅ F15 公告/知识库排序与分类管理(P2)

公告/知识库排序接口(单事务即时生效)+ 知识库分类 CRUD(存量数据迁移去重回填,有文档的分类拒绝删除)。

### ✅ F16 流量重置管理(P2)

按用户/批量清零用量或按套餐重新给量,保留重置记录;重置时保留 `node_user_stats` 快照防节点累计值重复计费。

### ✅ F19 主题系统(品牌配置子集)(P2)

管理端配置主色/背景图,前端运行时应用(设计令牌派生 + 暗色适配);完整主题包机制不做。

### ✅ F20 在线更新(版本检查子集)(P2)

`app.version` + 可选更新源 manifest,`GET /admin/version` 语义化版本比较;新管理页展示版本/变更日志;自动升级不做。

### ✅ F22 安全部署项(P2)

管理端/订阅路径段定制(启动注入)、`safe_mode` 域名白名单(非白名单 403,healthz/metrics 豁免)。

### ~~F01 礼品卡/兑换码系统~~(P0)

资金/收款变体,随支付方向整体排除;未来重启营销发卡需求时重估。

### ~~F03 多支付渠道接入~~(P0)

支付方向;现有 `pkg/payment.Driver` 注册表机制保留,后续按需单独评估驱动接入。

### ~~F06 订单管理增强~~(P1)

手动标记支付/改单核心是支付回调状态机与资金记账,属支付方向,随筛选排除。

### ~~F07 优惠券批量生成~~(P1)

优惠券方向,随筛选排除。

### ~~F13 快速登录(邮箱一键登录)~~(P2)

用户明确不需要;出现客服代登/免密场景时重估。

### F17 节点机器管理(P2)——缓排

当前手工对接 + node-agent-guide 已可运转;有批量部署节点需求时再立项(一键安装命令、负载历史)。

### ~~F18 节点路由~~(P2)

按套餐 `group_ids` 分组已覆盖主要场景;避免引入未验证复杂度,远期再评估。

### ~~F21 插件系统~~(P2)
